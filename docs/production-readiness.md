# OpenCode SDD production-readiness report

**Assessment date:** 2026-10-19  
**Target release:** stable 1.0.0 on npm and a separate public GitHub repository  
**Current package version:** 0.2.0 development release  
**Decision:** **Not production-ready for public launch yet.** The evidence-currency defect is fixed and locally tested. The packed tarball passed provider-denied real-host smoke on Windows and Debian 12. The public source commit passed the first Windows and Debian 12 GitHub Actions matrix on Node 22.14.0: 58 tests, package smoke, SDD verifying gates, clean-consumer installs and minimum/latest host smoke all passed. Both v2 aliases resolved to OpenCode 2.0.32. npm ownership, trusted publishing, a successful provider canary and publication gates remain open.

## Scope and release boundary

This report covers the current OpenCode v2 SDD plugin in this repository. The earlier private plugin repository is outside scope and must remain unchanged. The intended initial support is Debian Linux (the primary workspace), Windows, and Ubuntu/WSL compatibility; macOS is not claimed. Provider execution is disabled for smoke tests. The owner authorized one canary with `opencode-go/deepseek-v4.1-flash`, limited to included Go quota with no Zen Balance or top-ups. OpenCode returned `provider.no-route: Model unavailable`; no successful response was produced, and the canary remains unresolved. Details are in `.omo/evidence/production-readiness-provider-canary.md`.

Candidate names are `opencode-v2-sdd-plugin` on npm and `jd-chiles/opencode-sdd-v2` on GitHub. The separate public GitHub repository is owned by `jd-chiles`, and source commit `ef0af149e5e2f24cd905a154cbe8277ea523cc9c` is pushed. Its first CI matrix passed. npm's public registry lookup returned 404, but local npm identity lookup returned `ENEEDAUTH`, so npm account ownership/claimability remains unverified. Do not publish until authenticated npm ownership is verified.

## Material readiness work completed in this change

- Added worktree-content fingerprinting from Git's NUL-delimited committed paths, index paths, and non-ignored untracked paths. Fingerprints include normalized relative paths, executable state, regular-file bytes, symlink target bytes, and an explicit absent entry for tracked deletions. `.git`, ignored paths, index identity, and commit identity are excluded. Unsupported special nodes/submodules fail closed.
- Bound check and review execution to the worktree digest; check-time or review-time mutations fail verification. A full `/sdd-verify` records one final digest for all verified tasks; status recomputes current content and reports stale evidence after later edits.
- Added durable-state migration through schema v3: v1 history/session identifiers and v2 evidence are preserved; legacy verification remains historical pending explicit verification, and legacy research remains stale pending explicit refresh. Verification/refresh do not replay builders.
- Added deterministic tests for repeated same-length dirty edits, staged-then-edited files, nested untracked paths, deletion, staged deletion, rename, executable-mode changes on capable platforms, symlink targets when available, unchanged worktree across commits, state migration, mutation during verification, and stale evidence after later edits.
- Added MIT license, candidate public package metadata, 0.2.0 changelog, Debian/Windows CI configuration, package smoke checks for license/metadata, provider-denied host smoke for minimum/current v2 CLI, and a guarded 1.0.0-only OIDC release workflow.
- Corrected the tagged-release smoke to use the installed `bin/opencode.exe` ELF path and direct Node invocation on Linux; added a workflow-contract regression test to keep CI and release invocation aligned. The regression passed on Windows and Debian 12.
- Added Agentic SDD `doctor` and verifying gates to the Debian and Windows CI jobs, plus a complete-readiness check immediately before tagged npm publication. Added weekly `npm audit`, a production-only release audit, and Dependabot updates for npm and GitHub Actions. The current Debian source snapshot passed both audit commands with zero vulnerabilities. The first public GitHub Actions run also passed both platform jobs and all configured verifying gates.

## Remaining low-effort, high-impact improvements

The low-effort source and documentation improvements in this report are implemented: SDD CI/release gates, executable-mode regression coverage, recurring dependency audits and Dependabot, an evidence-linked signed release checklist, and user-facing support/migration boundaries. The public source has been pushed and its first Windows/Debian GitHub Actions matrix passed. Remaining work is account- and release-specific: configure and verify npm Trusted Publishing and `npm-production` reviewers, complete a successful provider canary under renewed bounded authorization, and verify the publishing account owns the npm name.

## Limitations

The Windows suite and OpenCode 2.0.32 host smoke ran locally against the installed tarball. Debian 12 current-source `npm ci`, 58-test suite, package smoke, clean consumer install, provider-denied OpenCode 2.0.32 host smoke, and executable-mode fingerprint coverage were exercised on the selected VPS. The public GitHub CI matrix passed on Windows and Debian 12 using Node 22.14.0 and OpenCode 2.0.32. Ubuntu WSL's earlier run used Node 18.19.1, below the declared Node >=22.14 floor; it is supplementary only. The first authorized provider attempt returned no route. The authorized same-model retry is indeterminate because it returned no visible result; provider acceptance and billing are unknown. No npm account ownership or trusted-publisher configuration has been authenticated. No GitHub release, npm version, provenance, or post-publication installation exists. The current version remains 0.2.0 and must not be treated as stable 1.0.0.
