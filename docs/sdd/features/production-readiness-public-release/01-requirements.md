# Requirements
Status: Approved scope; release gates remain conditional

- REQ-001: Verification evidence is bound to worktree content. Acceptance: deterministic SHA-256 over tracked and non-ignored untracked paths/content, including deletion and symlink representation; excludes commit identity and `.git`; checks and review fail if the tree changes during verification.
- REQ-002: Durable state is migrated safely. Acceptance: current schema is v3; v1 sessions/history and v2 evidence survive migration; legacy verification without a content fingerprint is historical and `/sdd-verify` rechecks without rerunning builders; legacy research without an input fingerprint remains stale until explicitly refreshed; status and ordinary execution do not represent legacy evidence as current.
- REQ-003: A current workflow verification covers the completed worktree. Acceptance: every task has evidence for the same final digest; any later mutation causes status to report stale until `/sdd-verify` passes again.
- REQ-004: Fingerprint behavior has comprehensive deterministic regressions. Acceptance: tests cover same-length repeated dirty edits, staged-then-edited files, nested untracked paths, deletion, rename, executable-mode changes where supported, symlink targets where supported, check-time mutation, post-verification mutation/resume, unchanged commits, and non-Git behavior as designed.
- REQ-005: Cross-platform support is continuously checked. Acceptance: CI covers Debian Linux as the primary workspace, Ubuntu/WSL compatibility where practical, and Windows on Node >=22.14; run typecheck, tests, package smoke, and provider-denied host registration for pinned minimum and release-freeze latest v2 versions where available. Resolve each OpenCode npm package's declared executable path for its platform and pass paths safely through each CI shell.
- REQ-006: Package is ready for public distribution. Acceptance: MIT license, complete metadata, public package setting, lockfile/changelog, documented npm plugin installation and separate bootstrap CLI, and tarball inventory review.
- REQ-007: Publication uses least privilege and provenance. Acceptance: validation and tagged-release workflows use minimal permissions; npm trusted publishing/OIDC is documented/configured without long-lived publish tokens; publication remains gated on name ownership, CI, host tests, provider canary approval, and final verification.
- REQ-008: Production readiness is evidence-backed. Acceptance: a report identifies completed, pending, and unexercised capabilities; no Linux/provider/release claim exceeds observed tests.
